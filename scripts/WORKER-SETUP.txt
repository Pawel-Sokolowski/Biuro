BIURO 1.5 - PROGRAM I WORKER Z JEDNEJ INSTALKI

1. Uruchom Biuro-Setup. Domyslnie zaznaczony jest tylko Program Biuro.
   Na serwerze zaznacz Worker (sam lub razem z programem).
   Zainstaluj proponowany sterownik ODBC, jesli chcesz czytac dane Enovy.
2. Po instalacji otworz z menu Start: Biuro - konfiguracja workera.
   Nie trzeba instalowac Pythona, tworzyc .venv ani uruchamiac skryptow.
3. Podaj PostgreSQL: IP/host, port, nazwe bazy, uzytkownika i haslo.
   Wybierz wspolny klucz z dzialajacego PC. Generowanie nowego jest tylko
   dla nowego biura. Sprawdz polaczenie, zapisz i zaloguj sie jako admin Biuro.
4. Uzupelnij i ZAPISZ ustawienia uslug w zakladkach: poczta, konto systemowe,
   przypomnienia, e-ZLA, odczyt z Enovy i KSeF. To te same ustawienia co w Biuro.
   Dla e-ZLA podaj login uslugi, haslo uslugi i haslo ZIP; zaznacz firmy.
   Enova wymaga przypisania nazwy bazy kazdej firmy. Wlasny certyfikat:
   zaznacz opcje zaufania certyfikatowi. Pliki zapytan SQL musza byc na serwerze.
5. W Zadania wybierz zadania, odstepy i wlacz worker; zapisz.
6. W Instalacja kliknij Zainstaluj autostart i uruchom worker.
   Zaakceptuj UAC NA TYM SAMYM KONCIE WINDOWS. W oknie aplikacji podaj
   haslo tego konta Windows (nie PIN, nie haslo Biuro).
7. Sprawdz swiezy sygnal i wyniki w Panel i logi. Zamkniecie panelu
   nie zatrzymuje workera. Dziala po restarcie i bez zalogowania Windows.

Menu Start -> Biuro Worker otwiera panel z przyciskami instalacji,
uruchamiania, restartu i zatrzymania (w oknie autostartu po UAC).

Konfiguracja konta Windows: %LOCALAPPDATA%\Biuro\worker.env
Logi: %LOCALAPPDATA%\Biuro\logs
Haslo Windows trafia do Harmonogramu Windows, nie do pliku konfiguracji.
Nie uruchamiaj drugiego workera dla tej samej bazy. Stare zadania migracyjne
wylacz dopiero po potwierdzeniu dzialania nowej instalacji.

Import e-ZLA DO ENOVY NIE JEST JESZCZE PODLACZONY.
Pobranie z ZUS do Biuro jest oddzielna operacja od importu do Enovy.
Nie ma tez jeszcze konektora SQL Platnika ani automatycznego podpisywania.
Deklaracje/UPO/kadry z Enovy wymagaja dopasowanych zapytan SQL.

Stare pliki .cmd/.ps1 pozostaja narzedziami pomocniczymi administratora.
Normalna instalacja nie wymaga ich otwierania. Nie uruchamiaj zadania
ponownie w celu testowania: wlaczone zadania moga wykonywac prawdziwe wysylki.
